CPCD Reading Notes: A Long-Horizon Campus Counseling Dialogue Dataset and Benchmark

Paper NotesMental HealthSynthetic DataBenchmark
August 21, 202615 min read

These are my reading notes on Psy-Chronicle: A Structured Pipeline for Synthesizing Long-Horizon Campus Psychological Counseling Dialogues. The paper addresses a practical limitation: most existing psychological-support data consists of single-turn exchanges or short conversations, while real psychological distress rarely emerges from one isolated event. It may begin with a failed exam, gradually affect sleep, relationships, and self-evaluation, and recur across multiple counseling sessions.

The paper makes three main contributions:

  1. Psy-Chronicle: a structured framework for synthesizing campus counseling dialogues over long time spans;
  2. CPCD (Chinese Psychological Counseling Dialogue Dataset): a Chinese long-horizon dialogue dataset for university counseling scenarios;
  3. CPCD-Bench: a benchmark that evaluates session-level response, long-term memory recall, and temporal-causal reasoning.

Psy-Chronicle Method

1. Student profile. For each synthetic student i, the framework first constructs a four-dimensional profile:

Pi={Bi,Ti,Si,Ci}(1)

Here, Bi, Ti, Si, and Ci denote demographic and academic background, personality tendency, family and social support background, and the core psychological conflict.

2. Temporal stress event graph. From the profile, the framework generates a stress event graph spanning the semester:

Gi=(Vi,Ei),Vi={vi,1,vi,2,…,vi,T}(2)

Vi is the sequence of stress-event nodes, while Ei captures temporal and developmental dependencies. Each node records the event, time, stress intensity, and dominant psychological state afterward. At weekly granularity, the system generates 10–15 events over 16 weeks in five campus domains: academic pressure, interpersonal relationships, career development, family and financial stress, and physical and mental health. caused_by edges organize these stressors into a coherent, evolving trajectory.

For example: in week 1, a student begins to doubt their ability because a major course is too difficult (E1). In week 4, a conflict with a roommate leads to social withdrawal (E2). By week 12, persistent academic stress and withdrawal jointly trigger insomnia and anxiety (E3). E2 can record caused_by: [E1], while E3 records caused_by: [E1, E2]. A later counseling session therefore sees not just “recent insomnia,” but how it developed from earlier academic frustration and interpersonal withdrawal.

3. Cross-session counseling simulation. Psy-Chronicle simulates multiple sessions along the event graph. At session t, the dialogue depends on the profile, current event, and accumulated memory:

Di,t=Φ(Pi,vi,t,Mi,t−1)(3)

Φ(·) represents the interactive simulation between a student agent and a counselor agent.

4. Structured memory update. After each session, a session-level summarizer Ψ(·) compresses the dialogue and updates historical memory:

Mi,t=Update(Mi,t−1,Ψ(Di,t,vi,t))(4)

The summary records the current stress event, dominant emotions, core conflict, counseling focus, and unresolved issues, then becomes context for future sessions. This avoids rereading every raw dialogue at each generation step while improving continuity and reducing factual drift.

The closed-loop process can therefore be written as:

Pi→Gi→{Di,t}t=1T→{Mi,t}t=1T(5)

Each session is explicitly tied to a stable profile, the current campus stress event, and accumulated counseling history. The final data also undergoes checks for structural completeness, semantic consistency, diversity, campus-scenario appropriateness, and safety boundaries.

Benchmark

CPCD-Bench tests more than whether a model can produce one plausible counseling response. It also tests whether the model can use cross-session history, track long-term changes in distress, and understand temporal and developmental relationships among stress events. Twenty complete student trajectories excluded from training are used to construct three complementary tasks.

How the Three Tasks Are Scored

SR · Session-level response

Given a student profile, current context, and historical memory, SR evaluates the model's next counselor response.

  • Empathy: whether it accurately recognizes and responds to the student's emotions and deeper meaning;
  • Coherence: whether it is consistent with the profile, trajectory, current expression, and counseling stage;
  • Professionalism: whether it maintains professional boundaries, stable communication, and risk awareness.

High-scoring responses show deep empathy, use context closely, and preserve professional boundaries. Superficial reassurance, ignored history, contextual conflict, lecturing, or potentially harmful language lowers the score.

MR · Memory recall

MR evaluates factual retrieval from long counseling histories using accuracy, completeness, temporal consistency, and hallucination control.

  • Accuracy: correctly recalling events, people, states, or values;
  • Completeness: covering the information requested;
  • Temporal consistency: preserving the correct order of events;
  • No hallucination: avoiding details absent from the history.

TCR · Temporal-causal reasoning

TCR evaluates how well a model organizes and explains the long-term development of psychological distress. Its dimensions are temporal accuracy, causal coherence, completeness, and hallucination control.

  • Temporal accuracy: organizing key events in the right order;
  • Causal coherence: explaining interactions and distinguishing triggers, amplifiers, and maintaining factors;
  • Completeness: covering key events and mechanisms;
  • No hallucination: avoiding invented events, diagnoses, behavior, or exaggerated conclusions.

A strong answer builds both a clear timeline and a defensible causal chain. Merely listing isolated events—or filling gaps with invented information—does not demonstrate an understanding of long-term change.

How Counseling Dialogues and Memory Are Generated

The counselor agent receives basic student information, historical memory, the current dialogue, and the counseling phase. To preserve information asymmetry, it does not see the complete internal profile or predefined core conflict, but must understand the student progressively through conversation. The core prompt also permits at most one question per turn, favors Socratic guidance, asks for concise conversational language, and requires strict adherence to the current counseling phase.

View the counselor agent's core prompt
Role: Counselor Agent

You are conducting the {session_id}-th counseling session
with student {student_name}.

Counseling Context:
- Basic information: {basic_info}
- Historical memory: {memory_summary}
- Dialogue history: {dialogue_history}

Current counseling phase:
{current_phase}

Phase instruction:
{phase_instruction}

Dialogue principles:
1. Ask at most one question in each response.
2. Use Socratic guidance rather than directly telling the student what to think,
   except in crisis-intervention situations.
3. Keep the response concise, natural, and conversational.
4. Strictly follow the current phase; do not rush into later-stage advice.

Please reply as the counselor. Output only spoken content.
Turns 1–8

Rapport and exploration

Use brief responses, minimal encouragers, and open questions to listen and clarify without rushing into analysis or advice.

Turns 9–12

Deeper exploration

Respond to expressed emotions, ask about concrete situations, clarify ambiguity, and connect prior counseling memory when needed.

Remaining turns

CBT-oriented intervention

Move through validation and empathy, identifying key thoughts or beliefs, open reflection, strategy exploration, and future-oriented encouragement.

Each session contains at least 20 and at most 30 turns. After the minimum, a closing phrase such as “see you next week” can end the session. The memory module then compresses it into a structured record:

{
  "session_id": "{session_id}",
  "week": "{week}",
  "emotional_state": "The student's dominant emotional state",
  "key_topics": "Key topics discussed in this session",
  "counselor_intervention": "Main interventions used by the counselor",
  "student_progress": "Student progress or resistance",
  "summary_text": "A summary of no more than 200 Chinese characters for later sessions"
}

How to Use the CPCD Dataset

CPCD is available on Hugging Face and ModelScope, while raw sessions are available in the author's GitHub repository. Data is organized by student trajectory: conversation/{session_num}/consultation_events_{case_id}.json stores raw dialogue for sessions 1–10, and the same case_id always refers to the same synthetic student.

  1. Split by trajectory. Divide training and validation data by student case_id, not by randomly splitting dialogue turns. Otherwise, the same profile and history may leak into both sets.
  2. Construct supervised fine-tuning examples. The paper's input combines profile, current context, memory summary, and necessary event background; the output is the target counselor response. Each counselor turn can become an instruction/input/output sample.
  3. Preserve intermediate structures. For research on long-term memory or event evolution, do not extract dialogue text alone. Profiles, event nodes, session IDs, and memory summaries are what distinguish CPCD from ordinary counseling corpora.

How to Score a System with CPCD-Bench

Benchmark tasks and history → target system responses → rubric-based Judge scores → aggregated task results.

  1. Evaluation tasks: CPCD-Bench inputs such as profiles, counseling histories, and current questions;
  2. Target model: the system being evaluated, such as a fine-tuned Qwen model, a RAG system, or an online API;
  3. Reference answer: an author-provided answer or key information that can support factual assessment;
  4. Judge model: a model that reads the task, target response, reference information, and rubric, then returns scores and reasons. The paper uses GPT-5.2.

Step 1: Choose the capability

  • SRG: provide profile, memory, and current dialogue; generate the counselor's next response;
  • MR: answer factual questions from the complete history to test cross-session memory;
  • TCR: reconstruct event development and explain causal relationships.

Step 2: Choose online or offline evaluation

Online mode is for models exposed through an OpenAI-compatible API. The script reads each task, calls the target model, and then asks the Judge to score the response.

Offline mode is for locally deployed or fine-tuned models. First answer every task locally and save the responses as a CSV. The evaluation script then reads those saved answers without needing access to the target model. At minimum, the CSV contains:

Example local-model response file
task_idmodel_response
SRG_001It sounds as though this exam result has made you question your ability…
SRG_002You mentioned that the insomnia became more noticeable after the conflict with your roommate…

Step 3: Generate the CSV with a local model

For SRG, the flow is: read one task JSON → combine profile, history, and current student utterance into a prompt → call the local model → write its answer and the original task_id to CSV.

A local inference script typically performs six operations:

  1. Load the model. Read the tokenizer and weights from the local model directory, place the model on an available GPU, and switch to inference mode.
  2. Read tasks. Traverse task JSON files in eval_task_info/srg. Every task has a unique task_id and an input_to_model object containing the context allowed for that task.
  3. Build the prompt. Extract the profile, previous counseling history, current event, dialogue context, and latest student utterance in a fixed order, then ask only for the counselor's next response.
  4. Call the model. Apply the model's own chat template, tokenize the prompt, and generate with consistent settings—for example, a fixed maximum length and no random sampling.
  5. Extract the answer. Keep only newly generated text, remove special tokens and surrounding whitespace, and store it as model_response.
  6. Write rows incrementally. Save the original task_id, response, and status after every task so completed answers survive an interrupted run.

Step 4: Run online evaluation

For SRG, this command generates responses and scores them in one run:

python eval_task_info/srg/srg_eval_online.py \
  --tasks "./eval_task_info/srg" \
  --rubric "./eval_task_info/srg/rubric.md" \
  --target-model "model/identifier" \
  --judge-model "openai/gpt-5.2" \
  --output "./outputs/srg_online_eval.jsonl" \
  --csv-output "./outputs/srg_online_eval.csv" \
  --resume
  • --tasks: task directory;
  • --rubric: scoring rubric used by the Judge;
  • --target-model: API identifier of the tested model;
  • --judge-model: scoring model;
  • --output: JSONL with per-task answers, scores, and reasons;
  • --csv-output: a tabular result file;
  • --resume: continue from existing results after interruption.

Step 5: Score locally generated responses

If responses are already stored in results/srg_my_model.csv, use the offline script:

python eval_task_info/srg/srg_eval_local.py \
  --input-csv "./results/srg_my_model.csv" \
  --tasks "./eval_task_info/srg" \
  --rubric "./eval_task_info/srg/rubric.md" \
  --judge-model "openai/gpt-5.2" \
  --output "./outputs/srg_local_eval.jsonl" \
  --csv-output "./outputs/srg_local_eval.csv" \
  --resume

The script matches each saved answer to its task and asks the Judge to score it.

Step 6: Understand a single response score

For one SRG response, the Judge assigns 1–5 points for empathy, coherence, and professionalism. If the scores are 4, 3, and 5, the response score is (4 + 3 + 5) ÷ 3 = 4.0. MR and TCR each use four dimensions and calculate their per-response averages in the same way.

Step 7: Calculate the final system results

Average every sample within the same task. For the 99 SR items: system SR score = sum of the 99 item scores ÷ 99. Compute MR over its 40 items and TCR over its 20 items separately. Report the result as, for example, SR = 4.02, MR = 3.71, TCR = 3.28.

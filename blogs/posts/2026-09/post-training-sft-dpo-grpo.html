大模型 Post-Training：从 SFT、DPO 到 GRPO

机器学习Post-Training模型对齐强化学习
2026 年 9 月 11 日约 18 分钟阅读

预训练让语言模型学会“什么文本可能接在后面”，Post-Training 则进一步塑造“面对一个请求，应该怎样回答”。SFT、DPO 和 GRPO 的核心差异在于它们分别从示范、偏好和奖励中学习。

“Post-Training”是一个宽泛的集合，并不只包含本文的三种方法。这里把范围限定在大模型预训练完成后的行为优化：让模型更稳定地遵循指令、呈现目标风格、满足人类偏好，或在数学、代码和工具调用等任务上探索更高奖励的策略。

先看全局：三种反馈，三种学习信号

Demonstration

SFT

给模型一个高质量回答，让它逐 token 模仿：“这样的答案值得学习。”

Preference

DPO

给模型同一问题下的一对回答，让它学习：“A 比 B 更符合偏好。”

Reward

GRPO

让模型现场生成多个回答，再由验证器判断：“这个回答能得多少分。”

记号：x 表示 prompt，y 表示模型回答，πθ 是正在训练的策略模型，πref 是冻结的参考模型，r(x,y) 是奖励或验证器分数。

SFT：从高质量示范中学习

Supervised Fine-Tuning（监督微调）使用形如 (prompt, answer) 的数据。训练时，模型看到 prompt 和标准回答的前缀，预测标准回答的下一个 token；预测错了，就通过更新参数。这与预训练仍然使用同一种语言建模机制，但数据分布、对话模板和损失区域已经面向具体行为。

交叉熵损失衡量模型给正确 token 的概率够不够高。例如，正确 token 是“苹果”时，模型只给它 5% 的概率，损失就很大；给它 90% 的概率，损失就很小。训练通过不断减小这个数值，让模型以后更倾向于预测出正确 token。

ℒSFT=−𝔼(x,y*)∼𝒟[∑t=1Tmtlogπθ(yt*|x,y<t*)] (1)

这里的 y* 是示范回答，mt 是 。对聊天模型而言，通常只在 assistant 的回答 token 上计算损失，而把 system 和 user token 作为条件；如果 mask 写错，模型可能花大量容量去背诵用户输入，甚至学会生成角色标记。

Loss mask 是一组标记，用来告诉训练程序哪些 token 需要计入损失。例如，可以把 assistant 回答的 token 标为 1，把 system、user 和补齐长度的 token 标为 0。标为 0 的内容仍会作为上下文提供给模型，只是不要求模型学习预测它们。

SFT 最擅长建立一个可靠的行为底座：教会模型聊天格式、任务边界、回答结构、领域术语和常见解题模式。

SFT 的优势

  • 目标稳定。本质是，工程链路成熟，调试也最直观；
  • 监督密集。一个回答里的每个目标 token 都能提供学习信号；
  • 格式控制强。对于 JSON、工具调用模板、固定报告结构等任务尤其有效；
  • 不需要在线采样。数据可以预先清洗、审查和复用。

最大似然训练就是让训练数据中的标准答案获得尽可能高的生成概率。例如，标准答案是“2”，训练就会调整模型，让它看到对应问题时更可能输出“2”。在 SFT 中，最大化标准答案的概率，与最小化前面介绍的交叉熵损失是同一件事的两种说法。

SFT 的边界

SFT 学到的是示范数据的条件分布。它只看到“应该输出什么”，看不到某个回答为什么优于另一个回答，也不会主动搜索数据中从未出现过的更优解法。教师强制训练时，模型总能看到正确前缀；真正生成时，它却必须继续自己的历史输出，因此训练分布与推理分布之间仍有差异。

实践中最容易出问题的往往不是公式，而是数据管线：训练与推理使用了不同 chat template、EOS 被截断、packing 打破样本边界、长回答因为 token 更多而权重过高，或训练轮数过多导致通用能力回退。训练 loss 下降只能说明模型更会拟合示范，不能代替真实生成评测。

DPO：把成对偏好直接写进损失函数

很多任务没有唯一标准答案。例如，两段解释都正确，但其中一段更清晰；两个客服回复都能解决问题，但其中一个更自然。此时，与其要求标注者写出理想答案，不如让他们在同一 prompt 的两个候选回答中选择更好的一个。DPO 使用的数据正是三元组 (x, y_chosen, y_rejected)。

传统 通常先用偏好对训练显式 reward model，再用 等算法优化策略。DPO 原论文从带 的奖励最大化问题出发，在 下，把隐式奖励改写为策略与参考策略的对数概率比：

RLHF 是“基于人类反馈的强化学习”。简单来说，先让人类比较同一个问题的多个回答，用这些选择训练一个会模仿人类偏好的奖励模型，再通过强化学习让语言模型更容易生成高分回答。它学习的是标注者表达的偏好，并不自动保证回答绝对正确。

PPO 是“近端策略优化”，是一种强化学习算法。它让模型提高高奖励回答的生成概率、降低低奖励回答的生成概率，同时限制每次参数更新的幅度。可以把它理解为：模型朝着奖励更高的方向学习，但每一步不要走得太远，以免原有能力突然遭到破坏。

KL 约束用于限制训练后的模型与参考模型相差太远。模型会努力生成奖励更高的回答，但如果变化过大，可能损害原有的语言能力，甚至学会利用评分规则的漏洞。KL 约束就像一根安全绳：允许模型朝更好的方向调整，同时对过度偏离参考模型的行为施加惩罚。

Bradley–Terry 偏好模型用两个回答的分数差，表示人类更喜欢其中一个回答的概率。例如，回答 A 的潜在分数远高于回答 B，人类选择 A 的概率就更大；两者分数相同时，各自被选择的概率约为 50%。DPO 借助这个假设，把“人类选择了 A 而不是 B”转化为可以训练模型的数学目标。

rθ(x,y)=βlogπθ(y|x)πref(y|x) (2)

同一个 prompt 下比较两个回答时，只依赖 r(x,y+) − r(x,y−)，只与 prompt 有关的未知归一化项会相互抵消。最终得到一个二分类形式的目标：

ℒDPO=−𝔼logσ(β[Δθ−Δref]) (3)

其中 Δθ = log πθ(y+|x) − log πθ(y−|x)，参考模型也计算同样的 Δref。因此 DPO 学习的是：相对于参考模型，进一步拉开 preferred 与 rejected 回答之间的概率差距。

这里的 π(y|x) 是整段 completion 的序列概率，log-probability 通常由回答 token 的 log-probability 求和得到。是否引入长度归一化会改变目标含义，不能在复现原始 DPO 时无条件把它改成每 token 平均。

freeze(reference_model)

for prompt, chosen, rejected in preference_data:
    chosen_margin = logp(model, prompt, chosen) - logp(reference_model, prompt, chosen)
    rejected_margin = logp(model, prompt, rejected) - logp(reference_model, prompt, rejected)
    loss = -logsigmoid(beta * (chosen_margin - rejected_margin))
    update(model, loss)

DPO 省掉了什么，又没有省掉什么？

DPO 不需要单独训练一个 reward model，也不需要在训练循环中用当前策略生成新回答，因此比典型的“reward model + PPO”链路更简单。但它并不是“没有奖励”：chosen/rejected 标签本身就在编码人类偏好；训练时也仍需一个冻结的 reference model，或预先缓存它对数据的 log-probability。

β 来自 KL 正则化的推导，控制策略偏离参考分布的尺度。在原始推导中，更大的 β 对应更强的参考约束；但实际训练后的 KL 还会同时受到数据、学习率、batch、训练步数和实现细节影响，因此不能只凭一个 β 值判断模型会偏移多少。

DPO 的常见陷阱

  • 相对更好不等于足够好。如果 chosen 只是“两害相权取其轻”，DPO 仍会把它当作正例；
  • 优化的是相对间隔。损失下降不保证 chosen 的绝对概率在每个样本上都上升；
  • 偏好可能存在捷径。长度、标题数量、礼貌套话或固定格式都可能被模型误当作质量信号；
  • 参考链路必须一致。policy 与 reference 的 tokenizer、chat template、截断方式和 response mask 应保持一致；
  • 离线数据限制探索。如果偏好集没有覆盖模型部署时会遇到的行为，DPO 不会凭空评价那些新区域。

GRPO：用组内相对奖励做在线优化

Group Relative Policy Optimization 最初由 DeepSeekMath 提出，是 PPO 的一种变体。它最重要的变化是：不再训练单独的 value/critic 模型来估计基线，而是针对同一个 prompt 采样一组回答，用这组回答的相对奖励估计 advantage。

  1. 组内采样：从旧策略 πold 为同一个 prompt 生成 G 个回答；
  2. 计算奖励：用规则验证器、程序测试、reward model 或它们的组合为每个回答打分；
  3. 计算相对优势：高于组内平均分的回答得到正 advantage，低于平均分的得到负 advantage；
  4. 更新策略：提高高优势回答的概率，压低低优势回答的概率，并通过 clipping 与可选 KL 项限制单次更新幅度。
Ai=ri−mean(r1,…,rG)std(r1,…,rG)+ε (4)

例如，同一道数学题生成四个答案，奖励分别为 [1, 1, 0, 0]。前两个答案高于组平均分，获得正优势；后两个获得负优势。如果四个回答全对或全错，组内方差接近零，这个 prompt 几乎无法提供相对学习信号。

更新时定义 token 级重要性比率 ρi,t = πθ(yi,t|x,yi,<t) / πold(yi,t|x,yi,<t)。GRPO 沿用 PPO 的 clipped surrogate：当新策略相对旧策略变化过大时截断比率，避免一次更新把概率推得过远。原始形式还加入相对参考模型 πref 的 KL 惩罚。

JGRPO=𝔼[1G∑i=1G1|oi|∑t=1|oi|{min(ρi,tAi,t,clip(ρi,t,1−ε,1+ε)Ai,t)−βDKL(πθ∥πref)}] (5)

公式 (5) 保留了原始 GRPO 的序列与 token 聚合，KL 项只写成了简记。对于 outcome reward，同一回答内的 token 共享一个组内优势；使用 process supervision 时，优势也可以随步骤变化。不同实现对 advantage 是否除以组内标准差、loss 按序列还是全局 token 聚合、KL 如何估计、一个 rollout 重复更新多少次，都可能有差异。比如当前 Hugging Face TRL 文档明确区分了原始 GRPO 与多种长度归一化变体，并允许关闭 KL；阅读实验结果时，不能只看“使用 GRPO”这个名称，还要核对实际 objective 和配置。

GRPO 为什么适合可验证任务？

数学最终答案、代码单元测试、结构化输出校验和部分工具调用任务，可以较低成本得到相对客观的 reward。在线采样让模型有机会探索 SFT 数据中不存在的解法，而组内比较又把不同题目的绝对难度部分抵消。DeepSeek-R1 进一步展示了大规模 RL 对推理行为的作用；同时，其 R1-Zero 实验也出现可读性差和语言混杂，说明“可以不先做 SFT”不等于“产品训练就应跳过冷启动数据”。

省掉 critic，不代表训练便宜

GRPO 省掉的是 value model。每个 prompt 要生成多个完整回答，在线生成通常正是主要成本。group size 太小，组内基线噪声大；group size 太大，采样成本迅速上升。更关键的是 reward：只要验证器存在漏洞，模型就可能学会利用漏洞，而不是完成真实任务。

  • 奖励稀疏：大量组全对或全错，advantage 接近零；
  • 奖励攻击：模型找到验证器没有覆盖的投机格式或边界条件；
  • 信用分配困难：最终答案奖励很难指出长推理链中究竟哪一步有价值；
  • 长度偏差：归一化方式可能系统性偏好更长或更短的回答；
  • 策略过期：rollout 被重复使用太久后，数据与当前策略之间的 off-policy 偏差增大。

反馈越自由，并不代表训练天然越强。当评价机制不可靠时，优化能力越强，模型放大代理目标错误的速度也可能越快。SFT 的“答案”昂贵但直接；DPO 把绝对评分降为两两比较；GRPO 允许在线探索，却把成败更多地交给 reward 设计。

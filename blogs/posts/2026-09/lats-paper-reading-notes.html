LATS《Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models》阅读笔记

论文阅读机器学习智能体树搜索
2026 年 9 月 14 日约 7 分钟阅读

这篇笔记阅读 Zhou 等人发表于 ICML 2024 的 Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models。论文提出的 Language Agent Tree Search（LATS）可以先用一句话理解：不要让智能体沿着第一次想到的行动一路走到底，而是在关键位置尝试几条分支，依据环境反馈决定继续哪条路。

贡献：给语言模型智能体加上“试路”和“回头”

LATS 把语言模型的三种用途放进同一套搜索过程：模型提出下一步的想法或行动，模型结合实际观察估计当前分支是否有希望，失败后模型再写反思；蒙特卡洛树搜索（MCTS）负责组织分支、选择下一条要探索的路径。工具或任务环境提供外部观察与最终反馈。这里的贡献不是训练出一个新模型，而是设计一种推理时的决策流程，让现成语言模型能利用多次尝试和真实反馈做规划。

背景：ReAct 为什么还不够

在 ReAct 中，模型通常按“思考 → 行动 → 观察”生成一条轨迹。例如购物智能体先搜一个关键词、点开商品、读描述，再决定是否购买。观察确实会影响下一步，但如果最早的搜索词选错，它通常不会在同一个决策点系统地比较其他搜索词。单纯把 ReAct 从头运行很多次，也没有让各次尝试共享“哪个分叉更值得继续”的搜索统计。

Tree of Thoughts 等方法会搜索多条思路，却主要在模型内部评价这些思路；面对网页、代码执行或知识检索，真实环境返回的观察往往比模型自己猜测更可靠。LATS 要连接这两边：像 ReAct 一样实际行动，同时像树搜索一样保留并比较备选路径。论文中的树节点不是一个新模型，而是“原始任务 + 到目前为止的行动、思考和环境观察”组成的部分过程；从同一节点采取不同下一步，就长出不同子节点。

方法：一次 LATS 搜索怎样运行

可以把它想成“带记录的试错”。假设任务是寻找符合指定条件的商品：模型可以分别提出两个搜索词，环境会返回两组商品；系统记录两条分支，先深入较有希望的一条。如果发现商品不符合要求，再回到之前的分叉点探索另一条。这只是帮助理解的示意例子，并非论文实验中逐字给出的轨迹。

  1. 选择：从任务起点沿搜索树走到一个待探索节点。MCTS 的选择规则同时考虑“目前看来有多好”和“这个分支探索得够不够”，避免只盯着早期高分路径。
  2. 扩展：让语言模型在这个节点生成多个候选想法或行动，例如不同的检索词、网页点击或代码方案；对可执行的行动，交给环境运行并取得观察，形成子节点。
  3. 评估：模型读到行动后的观察，再给子节点一个前景分数。论文还加入“自一致性”信号：同一状态多次采样时，反复出现的候选行动会获得额外支持。两种信号共同引导接下来的搜索；这里没有另行训练奖励模型。
  4. 模拟到终点：优先沿有希望的分支继续行动、观察和评估，直到得到答案、完成任务或到达步数限制；环境随后给出该轨迹的结果。
  5. 结果回传：把终点结果沿走过的路径写回各树节点的访问次数和价值统计，让后续选择知道哪条路已被证明更好或更差。这里的“回传”不计算梯度，也不更新语言模型参数。
  6. 失败反思：若尝试失败，模型生成一段文字说明可能哪里走错，把它存入记忆，供后续尝试参考。然后重复搜索，直到成功或用完预算。
和训练有什么区别？LATS 在使用模型回答一道题时花更多计算量搜索路径，属于推理时方法。模型充当行动生成器、状态评估器和反思撰写者，但其权重保持不变。MCTS 的“回传”更新的是当前任务的搜索树，不是 SFT、PPO 那样的参数训练。

不同任务会改变“行动”和“环境反馈”的具体含义：在 HotpotQA，行动可以是搜索或查询维基百科；在 WebShop，是搜索、点击等网页操作；在编程任务，一次行动可以是提交一份完整代码，编译器和测试结果就是观察。编程任务因为候选行动已经是完整解答，论文跳过继续模拟，直接用生成的测试用例通过率回传。纯推理的 24 点任务则以思维链作为分支，不需要网页工具。

实验：搜索带来了多少收益

多跳问答 HotpotQA：在论文选取的 100 道题、GPT-3.5 和相应搜索预算下，ReAct 的精确匹配率是 32%；独立运行 50 次再挑选的 ReAct 为 38%；LATS（以 ReAct 为基础）达到 63%。如果再结合 CoT 与 ReAct 提示，LATS 为 71%，但这是另一种更强的设置，不能把 71% 当作纯 ReAct 版的结果。消融实验中，去掉模型评分后只有 37%，去掉反思后为 58%，说明收益并非只来自“多试几次”。

程序生成 HumanEval：系统先让模型生成少量测试用例，用这些测试和编译反馈挑选代码；最后才用基准的真实测试评价选中的程序。GPT-3.5 下，ReAct、Reflexion、LATS 的 pass@1 分别为 56.9%、68.1%、83.8%；GPT-4 下，Reflexion 为 91.0%，LATS 为 92.7%。这里的提升同时依赖多候选搜索与可执行测试反馈，不能理解为一次生成就有同样效果。

网页购物 WebShop：在 50 条指令上，LATS 的平均匹配分为 75.9、完全成功率为 38%；同样设置 k=30 条轨迹的 ReAct best-of-30 分别为 59.1 和 32%，但两者每条轨迹的模型调用量不一定相同。论文列出的一个微调基线为平均分 67.5、成功率 45%：LATS 的平均匹配更高，但完全成功率反而更低，因此不能简单说它全面超过微调。24 点任务中，LATS（CoT）成功率为 44%，相比 RAP 的 40%，增幅较小。

怎么看这些结果

LATS 最能说明的是：当任务允许试多个分支、得到可信的外部反馈、再回到先前状态时，搜索可以比单条轨迹更有效地使用模型能力。但这些条件也是它的边界。HotpotQA 实验里，环境会在提交最终答案后直接告诉系统答得对不对，这是现实问答未必能取得的oracle 反馈；编程有测试可跑，购物环境有任务评分，也都比很多开放世界任务更容易评价。树搜索还要多次调用模型和环境，计算成本高于一次 ReAct；若真实行动不可撤销，也难以安全地回到旧节点。

我的理解是：ReAct 让模型边想边做，LATS 进一步决定“哪条边想边做的路线值得继续”。论文的重点不是让模型学会新的知识，而是把行动、观察、评估和反思组织成可回溯的搜索过程；效果好坏取决于外部反馈是否可信，以及任务是否值得付出多路径探索的成本。

SFT 监督微调

机器学习SFTPost-Training
2026 年 9 月 13 日约 8 分钟阅读

预训练后的语言模型已经会续写文字，但未必知道用户希望它怎样回答。监督微调（Supervised Fine-Tuning，SFT）给它看一批“问题—理想回答”的示范，让它练习在相似的上下文中生成这样的回答。

SFT 解决的问题

预训练主要让模型学会接着前文预测文本。它因此拥有语言和知识方面的能力，但“接着写得像训练文本”与“按用户要求给出合适回答”并不完全相同。例如，看到“为什么天空是蓝色的？”，模型可能续写另一个问题、模仿网页格式，或写出一段没有直接回答用户的文字。

SFT 用“指令 → 示范回答”把目标变得具体：遇到这种提问，应给出直接、清楚的解释；遇到格式要求，应按格式组织答案。它主要帮助模型把已有能力用于用户任务，也能让模型学习示范中出现的表达方式和知识，但并不保证每个事实都正确。

SFT 的实际算法

算法的核心仍是语言模型熟悉的“预测下一个 token”。区别在于：现在训练材料变成经过挑选的示范对话，训练目标集中在希望模型生成的回答上。下面用同一条样本走完数据、损失和参数更新。

  1. 准备示范数据。system 规定回答方式，user 给出问题，assistant 给出目标回答。这一条样本中的前两部分组成 x，最后一部分组成 y。
{
  "messages": [
    {"role": "system", "content": "请用通俗的中文解释科学问题。"},
    {"role": "user", "content": "为什么天空是蓝色的？"},
    {"role": "assistant", "content": "阳光进入大气后，蓝光更容易被空气分子散射，所以天空显得蓝。"}
  ]
}
  1. 转换成模型输入。训练程序用模型对应的对话模板把角色和内容排成一串 token。模型会读到整段对话；在一种常见的聊天式 SFT 设置中，只让 assistant 回答位置参与损失计算。这个位置选择叫 loss mask：system 和 user 没有被删掉，它们仍是生成答案所需的条件。不同数据格式也可以使用不同的 mask，具体取决于训练配置。TRL 的 SFT 文档给出了相关配置。
  2. 逐 token 计算损失。模型先读问题，再依次预测示范回答的下一个 token。训练时每一步都提供真实的回答前缀，供下一步继续预测；这叫 teacher forcing。如果正确 token 的概率只有 10%，这一位置的交叉熵损失约为 2.30；如果是 90%，损失约为 0.11。也就是说，模型越相信正确答案，损失越小。

以“只监督回答 token，并按这些 token 求平均”为例，训练目标可以写成：

ℒSFT(θ)=−1N∑(x,y)∈D∑t=1|y|logpθ(yt∣x,y<t)

D 是全部示范数据；x 是指令和上下文；y 是示范回答；yt 是回答中的第 t 个 token；y<t 是它前面的回答；pθ 是当前模型给正确 token 的概率；N 是参与损失计算的回答 token 总数。这个式子就是把正确 token 的负对数概率平均起来，也就是这里的交叉熵损失。最小化它，等价于尽量提高示范回答出现的概率，因此也叫最大似然训练。

  1. 更新并检查模型。用梯度下降降低上述损失，反复处理示范数据；然后在未用于训练的新问题上检查是否真的遵循指令。训练损失变小只说明模型更会预测示范，不能单独证明新问题也答得好。

整条主线是：预训练模型 → 指令与示范回答 → 对话模板和 loss mask → 预测回答 token、计算交叉熵 → 更新参数 → 用新问题验证。
